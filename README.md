# BulkMail – MERN Stack Bulk Email Application

A responsive React + Express + MongoDB application for an authenticated administrator to send permission-based email campaigns, review delivery history, and view basic analytics.

## Features

- React dashboard with Compose, Email History, and Analytics views
- Admin sign-in using credentials stored in environment variables
- Express API protected with JWT authentication
- Nodemailer SMTP integration
- Sends each message individually (recipient addresses are not exposed to other recipients)
- MongoDB stores campaign subject, body, recipient list, per-recipient delivery status, and timestamps
- Input validation, duplicate removal, maximum 50 recipients per campaign, login/send rate limits
- Responsive layout for desktop, tablet, and mobile
- Render Blueprint (`render.yaml`) for deployment and automatic deploys from GitHub

## 1. Requirements

- Node.js 20 or newer
- MongoDB Atlas database
- SMTP account/provider. For Gmail, use a Google App Password with 2-Step Verification; do not use your normal Gmail password.

## 2. Install and run locally

```bash
npm install
```

Copy `.env.example` to `.env` and fill in your values:

```env
MONGODB_URI=mongodb+srv://...
PORT=10000
NODE_ENV=development
ADMIN_EMAIL=admin@example.com
ADMIN_PASSWORD=use-a-long-unique-password
JWT_SECRET=use-a-long-random-secret-at-least-32-characters
SMTP_HOST=smtp.gmail.com
SMTP_PORT=465
SMTP_SECURE=true
SMTP_USER=your-email@gmail.com
SMTP_PASS=your-google-app-password
FROM_EMAIL=your-email@gmail.com
```

Start frontend and backend in development mode:

```bash
npm run dev
```

Open http://localhost:5173. The Vite dev server proxies `/api` requests to the Express server on port 10000.

For a production-style local test:

```bash
npm run build
npm start
```

Open http://localhost:10000.

## 3. MongoDB Atlas

1. Create a free MongoDB Atlas cluster.
2. Create a database user with a strong password.
3. Add a network access rule that permits your app host. For a quick learning test, `0.0.0.0/0` permits all source IPs; it is broad and not recommended for production. Prefer provider-supported static outbound IP ranges or private networking where available.
4. Copy the Node.js connection string and use it as `MONGODB_URI`. Add `/bulkmail` before the query string if your URI does not already specify a database.

## 4. SMTP setup

Set the SMTP variables in `.env`. For Gmail, enable 2-Step Verification and create an App Password in your Google Account. Use that app password as `SMTP_PASS`. Some SMTP providers require a verified sender address or separate SMTP credentials. Check the provider's sending limits and acceptable-use policy.

## 5. Push to GitHub

Create an empty GitHub repository, then run from this folder:

```bash
git init
git add .
git commit -m "Initial BulkMail MERN application"
git branch -M main
git remote add origin https://github.com/YOUR_USERNAME/YOUR_REPOSITORY.git
git push -u origin main
```

Never commit `.env`. It is ignored by `.gitignore`. If a secret is accidentally committed or shared, rotate it immediately; deleting the file in a later commit does not erase the secret from Git history.

## 6. Deploy on Render with Blueprint

1. Sign in at https://dashboard.render.com/ using GitHub.
2. Choose **New → Blueprint** and select your repository's `main` branch.
3. Render detects `render.yaml`. Review the service configuration and deploy.
4. In the service's **Environment** page, fill in `MONGODB_URI`, `ADMIN_EMAIL`, `ADMIN_PASSWORD`, `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASS`, and `FROM_EMAIL`. `JWT_SECRET` is generated by the Blueprint.
5. Save changes and redeploy if Render asks.
6. Open the Render URL. Sign in using the `ADMIN_EMAIL` and `ADMIN_PASSWORD` values you configured.

The Blueprint creates one Render web service that builds the React frontend and serves it from Express. Future pushes to the connected branch trigger automatic deployments.

## 7. Safety and sending limits

- Only send to people who have explicitly agreed to receive the messages. Respect removal/unsubscribe requests and applicable email laws/provider policies.
- Each campaign is limited to 50 unique recipients. The send endpoint is rate-limited and requires an authenticated admin.
- Each recipient gets a separate email; addresses are not placed in a shared To/CC list.
- This starter stores delivery attempts and SMTP acceptance/failure results. SMTP acceptance is not proof that a message reached the inbox; delivery, bounce, and spam-folder status require provider webhooks or delivery events.
- For production use, add a proper unsubscribe mechanism, suppression list, verified domain, SPF/DKIM/DMARC, background job queue, and provider webhooks before sending to larger lists.

## API

- `GET /api/health` – service and database health
- `POST /api/auth/login` – admin login
- `GET /api/mail/history` – latest 100 campaigns (JWT required)
- `GET /api/mail/stats` – aggregate stats (JWT required)
- `POST /api/mail/send` – send a campaign (JWT required)
